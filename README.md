# 끄적누구 · 낙서로 맞히는 자기소개

강의실 큰 화면 + 참가자 폰으로 30명이 함께 하는 아이스브레이킹 게임.

1. 진행자가 큰 화면에서 방을 열면 QR과 5자리 방 코드가 떠요.
2. 참가자는 닉네임만 적고 들어와 폰에 **내 얼굴 낙서 + TMI 세 줄**을 올려요 (기본 90초).
3. 큰 화면에 이름 없이 한 명씩 등장하면, 모두 20초 안에 폰으로 "누구게?"를 골라요. 주인공은 투표를 쉬어요.
4. 정답 공개 → 다음 주인공. 끝나면 **눈썰미 순위 · 미스터리상 · 낙서 갤러리**.

질문 세트(가벼운 기본 / 대학생·수강생 / 직장인 연수)를 고르고 질문 3개는 직접 고칠 수 있어요. 라운드 수(5~20명 또는 전원), 그리기·투표 시간도 정할 수 있어요.

## 배포 (Vercel)

1. vercel.com/new 에서 이 저장소를 가져오기 (설정은 기본값 그대로)
2. 프로젝트 → **Storage** → **Upstash for Redis** (Free) → 이 프로젝트에 연결
3. **Deployments** → 최신 배포 **Redeploy** (환경변수가 들어가도록)

저장소 설정은 이름이 어떻게 붙든 자동으로 찾아요: `KV_REST_API_URL/TOKEN`, `UPSTASH_REDIS_REST_URL/TOKEN`, 앞에 접두사가 붙은 이름(`STORAGE_KV_REST_API_URL` 등), 또는 TCP 주소(`REDIS_URL`, `KV_URL`, `*_REDIS_URL`).
`/api/health`에서 지금 어떤 저장소를 쓰는지(변수 **이름**만) 확인할 수 있어요.

Redis를 못 찾으면 로컬에서는 메모리 데모 모드로 돌고, Vercel에서는 방이 사라지는 걸 막으려고 방 만들기를 막고 안내를 띄워요(`KN_ALLOW_MEMORY=1`이면 허용).

## 개인정보

- 회원가입 없음, 닉네임만 받음. 사진·카메라 안 씀
- 그림과 답은 방 데이터로만 저장, 모든 키 2시간 TTL. 진행자 "끝내기"를 누르면 즉시 삭제
- 그림은 진행자 화면(또는 그린 본인)만 볼 수 있음

## 개발

```bash
npm install
npm run dev            # http://localhost:3000 (메모리 저장소)
npm test               # 순수 로직 테스트
npm run build && PORT=3100 npm start
BASE=http://localhost:3100 npm run sim   # 35명 가상 참가자 전체 게임 + Redis 명령 수 추정
```

실시간은 웹소켓 없이 1.5초 폴링이에요. 버전 번호만 먼저 읽고 바뀌었을 때만 상태를 가져오며, 서버 인스턴스마다 1초 마이크로캐시를 둬서 여러 폰의 폴링이 Redis 읽기 한 번을 나눠 써요.
